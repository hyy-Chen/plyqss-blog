> 运维工作里真正高频的不是重启服务，而是从一堆日志里找出「哪类请求在报错」、在几百行配置里改一个值、把一批主机上的旧配置替换掉。这篇把 `grep`/`sed`/`awk`/`xargs`/`jq` 串成一条流水线，重点是**组合思路和会踩的坑**，而不是逐个罗列参数。

## 一、先建立管道的心智模型

```text
command  ──stdout(1)──> 管道 ──> 下一个命令的 stdin(0)
         ──stderr(2)──> 默认直接打到终端
```

```bash
cmd > out.log                 # 覆盖重定向 stdout
cmd >> out.log                # 追加
cmd 2> err.log                # 只收 stderr
cmd > all.log 2>&1            # 合并（顺序不能写反）
cmd 2>&1 | tee all.log        # 既看又存
cmd | grep x | awk '{print}'  # 默认管道只传 stdout
```

两个关键事实：

1. **管道只传 stdout**，错误会漏到终端或被丢弃；日志分析时先决定要不要 `2>&1`。
2. **管道默认返回最后一个命令的退出码**，前面的 `grep` 失败会被吞掉。脚本里必须 `set -o pipefail`（见「Shell 脚本工程化」）。

## 二、工具分工

| 工具                   | 擅长                   | 典型用法                                      |
| ---------------------- | ---------------------- | --------------------------------------------- |
| `grep` / `rg`          | 按行筛选               | `grep -E '5[0-9]{2}'`、`rg -n 'timeout' /etc` |
| `sed`                  | 按行替换/删除/插入     | `sed -n '10,20p'`、`sed -i.bak 's/old/new/g'` |
| `awk`                  | 按列切分、统计、聚合   | `awk '{sum[$1]++} END{...}'`                  |
| `cut`                  | 简单按分隔符取列       | `cut -d, -f2,5`                               |
| `tr`                   | 字符级转换/压缩        | `tr '[:upper:]' '[:lower:]'`、`tr -s ' '`     |
| `sort` / `uniq`        | 排序与去重             | `sort                                         | uniq -c | sort -rn` |
| `wc` / `head` / `tail` | 计数与截取             | `wc -l`、`tail -f`                            |
| `xargs`                | 把行变成命令参数       | `xargs -r -n 10 cmd`                          |
| `jq`                   | JSON 提取与重组        | `jq -r '.level + " " + .msg'`                 |
| `paste` / `comm`       | 合并列、比较已排序集合 | 配置对比                                      |

选择顺序：**能用一次 `awk` 读完就别 `grep | cut | sort` 扫三遍**；大目录搜索用 `rg` 比 `grep -r` 快很多且默认忽略 `.git` 与二进制。

## 三、正则的最小必要集

| 写法                  | 含义                                    |
| --------------------- | --------------------------------------- |
| `^` / `$`             | 行首 / 行尾                             |
| `.` / `*` / `+` / `?` | 任意字符 / 前项重复 0+ / 1+ / 0 或 1    |
| `[0-9]{3}`            | 三位数字（需 `grep -E` 或 `sed -E`）    |
| `(a\|b)`              | 分组与或                                |
| `\b`                  | 单词边界（`grep -P` 支持更完整的 PCRE） |

`grep` 默认 BRE，`+`、`?`、`|`、`()` 要转义；用 `grep -E` 最省心。加 `-o` 只输出匹配部分、`-c` 计数、`-v` 反选、`-n` 带行号、`-F` 按字面量（搜索含正则符号的字符串时必备）。

## 四、awk 迷你教程

```bash
# 字段默认按空白分隔：$1 第一列，$NF 最后一列，NR 行号，NF 字段数
awk '{print $1, $NF}' access.log
awk -F',' 'NR>1 {print $2}' data.csv
awk 'BEGIN{print "ip,count"} {cnt[$1]++} END{for (k in cnt) print k,cnt[k]}' access.log
awk '$9 ~ /^5[0-9][0-9]$/ {print $7, $9}' access.log   # 条件过滤
awk '{sum+=$10; n++} END{printf "avg=%.2f n=%d\n", sum/n, n}' access.log
```

`awk` 是一次流式扫描完成过滤+聚合，对几百 MB 日志比「多次 grep 再排序」省得多。需要数值排序时用 `sort -k2,2nr`，或把结果交给 `sort` 处理。

## 五、五个能直接用的案例

### 1. 统计 5xx 最多的接口 Top 10

```bash
awk '$9 ~ /^5/ {print $7}' access.log \
  | sort | uniq -c | sort -rn | head -10
```

### 2. 按来源 IP 统计请求数

```bash
awk '{c[$1]++} END{for (ip in c) print c[ip], ip}' access.log \
  | sort -rn | head -20
```

### 3. 从 JSON 行日志里挑出超时错误

```bash
jq -r 'select(.level == "error" and (.msg | contains("timeout")))
       | [.ts, .service, .request_id, .msg] | @tsv' app.jsonl
```

### 4. 批量改配置：先备份、再预演、最后落盘

```bash
# 先看会改什么
sed -n 's/^worker_processes .*/worker_processes auto;/p' /etc/nginx/nginx.conf
# 带备份的替换
sed -i.bak.$(date +%F) -E 's/^worker_processes .*/worker_processes auto;/' /etc/nginx/nginx.conf
diff -u /etc/nginx/nginx.conf.bak.* /etc/nginx/nginx.conf || true
nginx -t && systemctl reload nginx
```

注意 `sed -i` 在 GNU 与 BSD/macOS 上语法不同（后者需要 `-i ''`），跨机器脚本要显式判断或使用临时文件 + `mv`。

### 5. 找出日志里耗时超过 1 秒的请求

```bash
awk '$NF ~ /^[0-9.]+$/ && $NF+0 > 1 {print $1, $7, $NF}' access.log \
  | sort -k3,3nr | head -20
```

`$NF+0` 是为了强制数值比较，避免字符串字典序把 `9` 排在 `10` 后面。

## 六、常见坑

| 坑                        | 后果                       | 解法                                                            |
| ------------------------- | -------------------------- | --------------------------------------------------------------- |
| `grep` 无匹配返回 1       | 在 `set -e` 脚本里直接中断 | `grep ... \|\| true`，或显式处理空结果                          |
| `xargs` 遇空格文件名      | 拆成两个参数               | `find ... -print0 \| xargs -0`，`xargs -r` 防空输入执行         |
| `LC_ALL` 不同导致排序差异 | 报表结果不一致             | 脚本开头 `export LC_ALL=C`，中文场景用 `zh_CN.UTF-8` 并全机统一 |
| `sort` 把大文件全量放内存 | 内存暴涨、磁盘临时文件     | 用 `sort -S 256M` 限内存，或先 `awk` 聚合再排序                 |
| `cat file \| grep x`      | 多一次进程与一次读         | `grep x file`                                                   |
| `sed -i` 无备份           | 改错无法回滚               | `-i.bak` 或先 `cp -a`                                           |
| `tail -f` 被日志轮转打断  | 转新文件后不再有输出       | `tail -F`（按文件名跟踪并重试）                                 |
| 用正则解析结构化日志      | 字段含空格/转义就错        | 结构化日志用 `jq`，别硬切字符串                                 |

还有一个隐蔽的：`awk` 里关联数组遍历顺序不保证，输出报表前一定要 `sort`，否则两次运行结果看着不一致，会被误判成数据抖动。

## 七、性能与可靠性建议

- **先过滤再聚合**：`awk` 里做条件判断，把不必要的数据挡在管道外。
- **一次扫描多输出**：一个 `awk` 里同时算计数、求和、最大值，避免重复读大文件。
- **`head` 提前终止**：`... | sort -rn | head -10` 会让上游在管道关闭时结束；但 `sort` 必须读完全量，别指望它提前。
- **大文件分块**：超大规模日志交给专用系统（Loki/ES），命令行只做临时抽查。
- **只读输入**：分析脚本绝不修改原始日志；输出写到单独目录并带时间戳。
- **把命令固化成脚本**：一次性临时命令容易漏引号、漏 `LC_ALL`；复用第二次就该写成带参数的脚本。

## 八、实践清单

- 脚本里固定 `LC_ALL`，并启用 `set -o pipefail`。
- 结构化日志用 `jq`，纯文本用 `awk` 一次扫描完成过滤与聚合。
- `find | xargs` 一律 `-print0` + `xargs -0 -r`。
- 批量替换先预演、留 `.bak`、改完做语法校验再 reload 服务。
- 报表输出前显式 `sort`，不要依赖 `awk` 数组顺序。
- 日志轮转场景用 `tail -F`；健康检查类管道加超时，避免挂死。
- 统计结果保留生成时间与输入文件范围，便于复盘时对齐数据口径。

## 九、面试速答

**Q：`grep | awk | sort | uniq` 这条链里管道传的是什么，退出码怎么算？**
只传 stdout，stderr 默认不进管道；整条管道的退出码默认是最后一个命令的，前面命令失败会被掩盖。脚本中用 `set -o pipefail` 让任一环节失败即整体失败。

**Q：文件名带空格，`find ... | xargs rm` 为什么危险？**
`xargs` 默认按空白分词，一个带空格的文件名会被拆成多个参数，可能删错或报文件不存在。用 `find -print0 | xargs -0 -r`，并先 `-print` 审阅范围。

**Q：为什么 `awk` 统计后还要 `sort`？**
`awk` 关联数组的遍历顺序不保证，直接输出会产生看似随机的顺序，甚至被误认为数据变化。显式 `sort -k2,2nr` 才能得到稳定、可比较的报表。

## 十、一句话收尾

文本处理的功力体现在**一次扫描、口径固定、结果可复现**：把筛选、聚合、排序放在同一条可控的流水线里，比记住多少个花哨参数都重要。
