## 一、结论

已有域名 `a.top`、没有服务器，同时希望博客具有较高的可玩性，推荐采用：

> `Quartz + GitHub Pages + GitHub Actions`

这个方案不需要购买或维护云服务器。文章以 Markdown 文件保存在 GitHub 仓库中，提交文章后由 GitHub Actions 自动构建静态网站，再发布到 GitHub Pages。域名 `a.top` 通过 DNS 指向 GitHub Pages。

选择 Quartz 的主要原因是它不仅是普通博客，还适合逐步发展成个人知识库或数字花园：

- 支持 Markdown 写作，迁移和备份简单；
- 支持双向链接、反向链接、标签、目录和知识图谱；
- 支持全文搜索、代码高亮、目录导航和暗色模式；
- 可以通过主题、组件和 CSS 定制页面；
- 所有内容都是静态文件，访问速度快，部署成本低；
- 后续可以加入评论、统计、RSS、友链和自动化发布。

## 二、为什么不选 Astro + MDX

`Astro + MDX` 也很优秀，更适合制作高度定制的个人主页、产品展示页和带有复杂交互的博客。它的自由度很高，但通常需要自己设计文章布局、知识库功能、双向链接和页面组件。

当前目标是“先搭建一个可持续写作、又有较高可玩性的博客”，Quartz 已经提供了数字花园常用能力，前期配置成本更低，因此优先选择 Quartz。将来如果需要完全自定义视觉和交互，再迁移到 Astro 也可以。

## 三、整体架构

```text
本地电脑
   │
   │ 编写 Markdown 并提交
   ▼
GitHub 仓库
   │
   │ GitHub Actions 自动构建
   ▼
GitHub Pages 静态站点
   │
   │ DNS 解析 + HTTPS
   ▼
https://a.top
```

各部分职责如下：

| 部分           | 作用                                     |
| -------------- | ---------------------------------------- |
| Quartz         | 将 Markdown 内容构建为静态网页           |
| GitHub 仓库    | 保存源码、文章、图片和配置               |
| GitHub Actions | 自动安装依赖、构建并发布网站             |
| GitHub Pages   | 提供免费的静态文件托管                   |
| DNS            | 将 `a.top` 指向 GitHub Pages             |
| Giscus         | 可选的基于 GitHub Discussions 的评论系统 |

## 四、部署流程

### 1. 准备 GitHub 仓库

建议新建一个专门的公开仓库，例如：

```text
blog
```

Quartz 源码和文章都放在这个仓库中。仓库公开后，GitHub Pages、Giscus 评论和部分搜索引擎收录能力会更容易配置。

### 2. 初始化 Quartz

可以使用 Quartz 官方模板创建博客，然后把仓库克隆到本地：

```bash
git clone <你的博客仓库地址>
cd blog
npm install
```

本地预览通常使用：

```bash
npx quartz build --serve
```

浏览器打开命令输出的本地地址，确认文章、导航、标签和链接效果。

### 3. 编写第一篇文章

Quartz 的文章一般使用 Markdown 文件，并通过 Front Matter 设置标题、标签和发布时间。例如：

```markdown
---
title: 我的第一篇文章
tags:
  - 随笔
  - 博客
draft: false
---

# 我的第一篇文章

这里开始记录内容。
```

建议先建立以下内容结构：

```text
content/
├── index.md
├── 关于我.md
├── 博客搭建记录.md
├── 技术笔记/
└── 随笔/
```

### 4. 配置 GitHub Pages

将 Quartz 的 GitHub Actions 工作流提交到仓库后，在 GitHub 仓库中进行以下配置：

1. 打开 `Settings` → `Pages`。
2. 将发布来源设置为 `GitHub Actions`。
3. 推送代码到默认分支。
4. 等待 Actions 构建完成。
5. 先使用 GitHub 提供的临时域名确认网站可访问。

Quartz 的构建配置应确保最终输出目录被 Actions 正确发布。首次部署失败时，优先查看仓库的 `Actions` 日志，常见原因是 Node.js 版本、依赖安装或发布目录配置不匹配。

### 5. 绑定 `a.top`

在 GitHub Pages 的 `Custom domain` 中填写：

```text
a.top
```

然后到域名服务商配置 DNS。

如果使用根域名 `a.top`，通常配置 GitHub Pages 提供的 IPv4 地址：

```text
类型：A
主机记录：@
记录值：GitHub Pages 官方提供的地址
```

如果还希望使用 `www.a.top`，可以增加：

```text
类型：CNAME
主机记录：www
记录值：<你的 GitHub 用户名>.github.io
```

具体 IP 地址和 CNAME 目标应以 GitHub Pages 当前文档显示的值为准，不要直接照抄来源不明的地址。DNS 生效后回到 GitHub Pages 页面检查域名，并开启 `Enforce HTTPS`。

### 6. 验证发布链路

完成配置后，按以下顺序验证：

1. 修改一篇 Markdown 文章。
2. 提交并推送到 GitHub。
3. 查看 `Actions` 是否自动运行。
4. 确认构建任务成功。
5. 访问 `https://a.top`，确认新文章已经发布。
6. 检查文章链接、图片、搜索、暗色模式和移动端显示。

## 五、推荐的增强功能

### 1. Giscus 评论

Giscus 使用 GitHub Discussions 保存评论，不需要单独购买数据库或服务器。适合公开技术博客，但需要：

- 博客仓库公开；
- 仓库开启 Discussions；
- 安装 Giscus GitHub App；
- 在 Quartz 中填入仓库标识和分类信息。

评论区依赖 GitHub，国内访问体验可能受网络环境影响，可以先不配置，等博客内容稳定后再添加。

### 2. 知识图谱和双向链接

这是选择 Quartz 的核心理由。文章之间可以互相链接，逐步形成个人知识网络。例如在学习 Go 时，可以把文章连接到并发、调度器、内存模型等主题。相比单纯按时间排列的博客，这种方式更适合长期积累。

### 3. 全文搜索和标签

为文章统一设置标签，例如：

```text
Go、数据库、系统设计、读书、随笔
```

标签不宜过多。建议先使用稳定的主题标签，再利用双向链接补充细粒度关联。

### 4. 图片和附件

优先将文章配图压缩后放入仓库，目录与文章保持清晰对应。图片较多时，可以考虑对象存储或图床，但需要额外管理访问权限、域名和失效风险。

### 5. 统计和订阅

后续可以增加轻量级访问统计、RSS 和邮件订阅。统计工具应优先选择隐私友好、无需自建服务器的方案，避免为了统计功能重新引入后端维护成本。

## 六、成本与限制

### 成本

- 域名：已有 `a.top`，只需承担续费费用；
- GitHub Pages：个人静态站点通常可以免费使用；
- GitHub Actions：个人博客的构建频率通常足够使用；
- 服务器：不需要购买。

### 限制

- 只能直接运行静态内容，不能在 GitHub Pages 上运行 Go、Node.js 服务端接口；
- 评论、点赞、登录等动态功能需要第三方服务；
- 仓库中的大文件会增加构建和拉取时间；
- GitHub Pages 的访问速度和可用性受网络环境影响；
- 如果未来需要用户登录、后台管理、支付或实时数据，应迁移到云服务器、Serverless 或专门的托管平台。

## 七、最终落地顺序

建议按以下最小可行路线执行：

1. 注册或确认 GitHub 账号，并创建公开博客仓库。
2. 使用 Quartz 模板初始化项目。
3. 修改站点标题、作者信息、主题色和头像。
4. 写入三篇文章：关于我、博客搭建记录、第一篇技术文章。
5. 配置 GitHub Actions 和 GitHub Pages。
6. 绑定 `a.top` 并开启 HTTPS。
7. 确认手机端、文章链接、图片和搜索功能正常。
8. 再添加知识图谱、Giscus 评论、RSS 和访问统计。

不要一开始就追求复杂主题和大量插件。先让“写 Markdown → 推送 GitHub → 自动上线”这条链路稳定，再逐步增加可玩功能，维护成本最低。

## 八、方案结论

对于当前条件，最合适的组合是：

```text
内容主体：Quartz
代码与文章：GitHub 仓库
构建发布：GitHub Actions
静态托管：GitHub Pages
访问域名：a.top
评论系统：后续按需接入 Giscus
```

它的核心优势是：不用服务器也能拥有一个完整博客，同时保留数字花园、知识图谱和主题定制等较高的可玩性。
