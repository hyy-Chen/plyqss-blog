## 1. 如何防御 SQL 注入？

**回答：** 值参数使用预编译占位符；表名、列名和排序方向采用服务端白名单，绝不拼接不可信输入。

**补充：** 参数化不能替代权限最小化、审计和错误信息控制。不要把数据库账号授予不必要的 DDL/DROP 权限。

## 2. 什么是 SSRF？

**回答：** 攻击者诱导服务端请求其指定 URL，从而访问内网服务、云元数据或扫描端口。

**补充：** URL 抓取、Webhook、图片代理最危险。限制协议、域名/目标 IP 白名单，解析后拦截私网/环回地址，并限制重定向、超时和响应大小。

## 3. Session 与 JWT 如何选择？

**回答：** Session 状态在服务端，易撤销；JWT 可无状态验证，便于分布式，但撤销、泄露和过期管理更复杂。

**补充：** JWT 不应放敏感数据，必须验证签名、算法、过期、issuer/audience。浏览器场景还要处理 Cookie 的 Secure、HttpOnly、SameSite 和 CSRF。

## 4. 密码如何存储？

**回答：** 使用 bcrypt、scrypt 或 Argon2 等专用慢哈希加盐，绝不明文或普通 MD5/SHA 哈希。

**补充：** 密码重置令牌应随机、高熵、短过期、一次性使用；日志、指标、错误响应均不得输出密码、Token 或完整个人信息。

## 5. 为什么需要限流？

**回答：** 限流保护服务与下游，防止攻击、突发流量和重试风暴耗尽资源。

**补充：** 常用固定窗口、滑动窗口、令牌桶、漏桶。限流键可按 IP、用户、接口或租户；拒绝时返回明确状态并保留必要的观测指标。
