> 面向后端工程师，默认以 Redis 7.x 为背景。每题的“回答”适合直接作答，“补充”用于应对追问。

## 1. Redis 为什么快？

**回答：** Redis 的数据主要在内存中，命令执行路径短；它用 I/O 多路复用管理大量连接，单线程顺序执行大部分命令，避免了多线程锁竞争。

**补充：** 快不等于没有瓶颈。大 key、`O(N)` 命令、慢 Lua 脚本、网络和持久化 fork 都可能造成延迟；Redis 6 起 I/O 可使用线程，但命令执行仍主要由主线程完成。

## 2. Redis 有哪些常用数据类型？

**回答：** String、Hash、List、Set、ZSet，以及 Stream、Bitmap、HyperLogLog、Geo 等扩展结构。

**补充：** 类型应按访问模型选：计数器用 String，标签去重用 Set，排行榜用 ZSet，消息流可用 Stream。不要把所有对象都 JSON 序列化进 String，否则会失去字段级操作能力。

## 3. String 的常见内部编码是什么？

**回答：** 整数值可用 `int` 编码，短字符串常用 `embstr`，较长字符串用 `raw`；底层字符串实现是二进制安全的 SDS。

**补充：** SDS 保存长度和剩余空间，取长度为 `O(1)`，追加时可预分配，且能包含 `\0`。编码是实现细节，业务不应依赖某一编码阈值。

## 4. Hash、List、Set、ZSet 分别适合什么场景？

**回答：** Hash 适合对象字段，List 适合队列，Set 适合去重和集合运算，ZSet 适合带分数排序和范围查询。

**补充：** ZSet 同时维护成员到分数的映射与按分数排序结构；集合过大时，一次返回全部成员会阻塞，应使用 `SSCAN`/`HSCAN` 等渐进遍历。

## 5. Redis 的过期键会立刻删除吗？

**回答：** 不保证。Redis 采用惰性删除和定期删除：访问时删除过期键，后台周期性抽样清理。

**补充：** TTL 是近似到期语义，不能作为严格定时任务。缓存过期后可能仍暂占内存；内存不足时是否淘汰还由 `maxmemory-policy` 决定。

## 6. RDB 和 AOF 有什么区别？

**回答：** RDB 是某时刻的紧凑快照，恢复快；AOF 记录写命令，数据丢失窗口通常更小。生产常同时启用。

**补充：** RDB 的 `BGSAVE` 和 AOF 重写都会 fork 子进程，写入很高时 COW 会产生额外内存压力。AOF 的 `everysec` 是常用折中，异常断电可能丢最近约一秒数据。

## 7. 什么是缓存穿透、击穿和雪崩？

**回答：** 穿透是查询不存在的数据；击穿是热点键失效时大量请求同时回源；雪崩是大量键同一时间失效或缓存整体不可用。

**补充：** 穿透可用空值缓存/布隆过滤器；击穿可用互斥重建或逻辑过期；雪崩可通过 TTL 抖动、限流、降级和多级缓存缓解。

## 8. Redis 的 `SET key value NX EX seconds` 能做什么？

**回答：** 可原子地“仅当 key 不存在时设置值并设置过期时间”，常用于简单分布式锁或幂等占位。

**补充：** 释放锁必须校验 owner token，不能直接 `DEL`，否则可能删掉过期后被其他请求获得的锁；比较和删除应使用 Lua 保证原子性。

## 9. 为什么不建议使用 `KEYS *`？

**回答：** `KEYS *` 会遍历整个键空间，时间复杂度为 `O(N)`，大库中会阻塞 Redis 主线程。

**补充：** 线上用 `SCAN` 分批遍历，但 `SCAN` 允许重复或漏看正在变化的元素，不能把它当作强一致快照。

## 10. 什么是大 key，为什么危险？

**回答：** 大 key 指 value 很大或集合元素很多的 key。它会拉长单次命令耗时、网络传输和持久化时间，也会导致删除或迁移阻塞。

**补充：** 用 `redis-cli --bigkeys`、`MEMORY USAGE` 和采样监控识别。拆分为多个小 key，删除大 key 时考虑 `UNLINK` 异步释放内存。

## 11. Go 服务如何使用 Redis 客户端？

**回答：** 复用并发安全客户端和连接池，为每次命令传递带超时的 `context`，不要每个请求新建连接。

**补充：** 连接池满常反映命令慢、网络异常或下游阻塞；要设置读写超时、池大小和重试边界，不能无限自动重试非幂等命令。

## 12. Redis 能替代 MySQL 吗？

**回答：** 通常不能。Redis 适合缓存、会话、计数、排行榜等低延迟场景；MySQL 更适合事务性持久数据、复杂查询和约束。

**补充：** Redis 持久化与复制并不等于关系型事务数据库。关键业务数据应明确权威存储，缓存失效、重建和一致性都要有设计。
