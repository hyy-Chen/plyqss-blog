> StarRocks 是面向实时分析的 MPP 列式数据库。本文以共享无状态计算与可选共享数据架构为主，具体能力应以所用版本文档为准。

## 一、架构与角色

StarRocks 将控制、计算与存储职责拆开。FE（Frontend）负责元数据、SQL 解析优化、调度与事务协调；BE（Backend）提供存储和计算；在存算分离部署中，CN（Compute Node）承担无状态计算，数据可存放在对象存储中。

```text
客户端 → FE（解析、优化、调度） → BE/CN（扫描、Join、聚合、交换）
              │                         │
              └── 元数据与副本管理       └── Tablet / 列式数据 / 缓存
```

查询被拆成多个 Fragment，在节点间通过 Exchange 传输中间结果。MPP 的价值是将扫描、聚合与 Join 并行到多个节点；数据分布是否均衡直接影响实际速度。

## 二、表模型、分区与分桶

StarRocks 使用分区（partition）做数据生命周期管理，并将每个分区拆为多个 Tablet；Tablet 是副本、调度和迁移的基本单位。分桶（bucket）根据分桶键将数据散列到 Tablet，影响 Join 数据交换和数据倾斜。

| 表模型        | 核心语义                        | 适合场景               |
| ------------- | ------------------------------- | ---------------------- |
| Duplicate Key | 保留明细行                      | 日志、行为明细         |
| Aggregate Key | 相同 key 的聚合列按聚合函数汇总 | 预聚合指标             |
| Unique Key    | 相同 key 保留最新值             | 用户画像、订单状态     |
| Primary Key   | 主键语义与高效更新/删除         | 实时维表、频繁变更数据 |

模型选择决定写放大、查询路径和更新语义。不要因“看起来去重”就混用 Unique Key 与 Primary Key；应按版本实现和更新频率评估。

## 三、列式存储与向量化执行

数据按列组织，扫描只读取查询涉及的列；同列值类型相同，适合字典、RLE、位图等编码压缩。列式布局在聚合分析中显著降低 I/O，但对逐行点查和频繁小更新不如行存数据库自然。

执行引擎按列向量（batch）处理数据，利用 SIMD 和紧凑内存布局降低逐行解释开销。优化器会做谓词下推、列裁剪、分区裁剪、Join 重排与运行时过滤（Runtime Filter）：例如构建端 Join key 可生成过滤器，提前减少探测表扫描数据。

## 四、写入、事务与 Compaction

导入可通过 Stream Load、Broker Load、Routine Load（Kafka）等方式进行。数据先写入新的版本，再由 FE 协调提交，使读取侧看到一致快照。副本机制保障 Tablet 数据可用，副本数与存储成本、容错能力相互权衡。

列式系统会产生多个数据文件/版本；Compaction 在后台合并小文件、清理旧版本并改善读取效率。高频小批量写入会增加版本与 Compaction 压力，实践中应尽量批量导入并监控写入延迟、版本数和 Compaction backlog。

## 五、物化视图与实时分析

物化视图预先保存查询结果或明细的派生结构。优化器在查询可被改写时使用物化视图，从而减少扫描和聚合；异步物化视图可从外部表或内部表定期刷新。它不是无成本索引：需要额外存储、刷新资源，并且结果新鲜度由刷新策略决定。

对于湖仓分析，StarRocks 可读取 Hive、Iceberg、Hudi、Delta Lake 等外部表并使用缓存、谓词下推和 CBO。外表数据的文件组织、分区设计和元数据新鲜度仍会决定性能。

## 六、性能与排查要点

1. 分桶数不能机械设置过大或过小：过小限制并行度，过大增加 Tablet 元数据与小文件开销。
2. 高基数字段、热点 key 或时间分区不均都可能造成数据倾斜；查看各节点扫描行数与耗时而非只看总耗时。
3. 优先让过滤条件命中分区裁剪与列裁剪；避免 `SELECT *` 扫描宽表。
4. 明细与聚合负载的表模型、排序键和物化视图策略应分开设计。

排查 SQL 时使用 `EXPLAIN`、Query Profile 和审计日志，重点观察扫描行数、分区命中数、Shuffle 量、Runtime Filter 命中率、各算子峰值内存和长尾节点。
