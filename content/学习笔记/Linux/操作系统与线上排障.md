## 一、排障原则

先确认影响范围和时间窗，再分 CPU、内存、磁盘 I/O、网络、连接与下游依赖排查。不要看到 CPU 高就立即重启；先保留指标、日志、profile 和现场信息。

| 现象     | 首查指标/命令              | 常见原因                     |
| -------- | -------------------------- | ---------------------------- |
| CPU 高   | `top`、`pidstat`、pprof    | 热循环、序列化、GC、锁竞争   |
| 内存增长 | RSS、heap pprof、`dmesg`   | 无界缓存、泄漏、OOMKill      |
| I/O 高   | `iostat -x`、`iotop`       | 慢盘、刷盘、日志、Compaction |
| 连接异常 | `ss -s`、`ss -tan`、`lsof` | 连接泄漏、TIME_WAIT、下游慢  |

## 二、面试题

## 1. load average 是什么？

**回答：** load average 表示运行队列和不可中断睡眠任务的平均数量，不等同于 CPU 使用率。

**补充：** load 高可能是 CPU 饱和，也可能是磁盘 I/O 导致大量 D 状态进程。应结合 CPU、iowait、进程状态和磁盘指标判断。

## 2. 什么是文件描述符耗尽？

**回答：** 进程/系统打开文件、socket、pipe 都占 FD；超过 `ulimit -n` 或系统限制后，新连接/文件打开会失败。

**补充：** 用 `lsof -p PID` 和 `/proc/PID/fd` 查数量与类型。HTTP response body、DB rows、文件和连接必须显式关闭。

## 3. 如何排查接口 CPU 飙高？

**回答：** 确认具体 PID/线程后，结合应用 profile 找热点函数，再判断是业务计算、GC、锁竞争还是系统调用。

**补充：** Go 服务优先采 CPU pprof；不要只凭 `top` 猜测。修复后对比 QPS、P99 和 CPU，而不是仅看瞬时下降。

## 三、常用命令

```bash
top -H -p <pid>          # 线程级 CPU
ss -tan                  # TCP 状态
lsof -p <pid>            # 文件描述符
vmstat 1                 # 运行队列、上下文切换、swap
iostat -x 1              # 磁盘利用率与等待
```
